## 1. Product target

SuperBook should turn a literary passage into a **living illustrated story moment**.

Target pipeline:

**passage → AI scene direction → high-quality illustrated scene → animation-ready character assets → local articulated puppet → continuous acting**

This is NOT:

- a static AI image;
- a slideshow of AI images;
- camera pan/zoom presented as acting;
- primitive vector/stick characters;
- paid text-to-video;
- per-frame AI inference.

Desired example:

A detailed illustrated room with two characters. One can enter, walk, settle, talk, gesture, reach for food, eat, listen/react, and return to idle. Motion must be continuous and locally generated by the runtime.

## 2. Critical discoveries from previous POCs

The supplied `SuperBook_Real_Scene_MIN(1).html` is unsuitable as the final visual source. Its embedded background is approximately 709×890 and already visibly pixelated. Cropping/masking its head/hands and rotating those pieces produced the rejected “moving stones” effect.

The high-quality AI keyframe was the correct visual direction. The mistake was trying to animate it by generating three edited still images.

## 7. /puppet-sheet contract

Request:

```json
{
  "character": "one character description"
}
```

Intended response:

```json
{
  "schemaVersion": "1",
  "mimeType": "image/png",
  "base64": "...",
  "assetType": "animation-ready-character-sheet",
  "sourceModel": "..."
}
```

The generated sheet is supposed to contain one consistent character on a simple background, with separated parts:

- head;
- torso;
- upper/lower arms;
- hands;
- upper/lower legs;
- feet;
- neutral full-body reference.

The next stage should crop/segment those parts and assign pivots.

## 8. Puppet runtime architecture

File:

`poc/puppet_runtime_foundation/puppet_runtime.js`

Semantic parts:

- `head`
- `torso`
- `armR`
- `handR`
- `armL`
- `handL`
- `legR`
- `legL`

Pivots:

- neck;
- spine;
- shoulderR / elbowR;
- shoulderL / elbowL;
- hipR / hipL.

Supported action vocabulary:

- idle
- walk
- talk
- gesture
- eat
- listen

The foundation already demonstrates deterministic continuous values for breathing, head movement, arm movement and action-specific gestures.

It is **not yet connected to generated character artwork**.

## 9. Next implementation sequence

### Gate A: asset generation

1. Deploy the Worker branch.
2. Confirm `/health`.
3. Run smoke workflow.
4. Open Puppet Asset Lab.
5. Inspect the generated sheet.

If the sheet is poor, fix generation before writing more runtime code.

### Gate B: part extraction

Use deterministic browser-side processing first.

If the blue background is consistent, chroma-key it and crop the semantic regions. Generate transparent part images and pivot metadata.

Do not immediately build a complicated AI segmentation system.

### Gate C: one-character puppet

Render real generated artwork parts in a canvas/runtime.

Required continuous motion:

- breathing;
- head turn;
- shoulder response;
- elbow movement;
- wrist/hand movement;
- gesture;
- reach;
- hand-to-mouth eating;
- listening tilt;
- walk cycle.

This is the first meaningful quality gate.

### Gate D: two-character interaction

Add the second character and a detailed room/background.

Test:

- character A talks;
- character B listens;
- A gestures;
- A reaches for food;
- A eats;
- B reacts;
- both return to idle.

### Gate E: AI scene director

Connect the existing ScenePlan to the puppet runtime.

AI should supply intent such as:

- actor;
- action;
- target;
- emotion;
- duration;
- interaction order.

The runtime should translate that into local animation.

**No per-frame AI.**

## 15. Core architectural principle

The correct division of responsibility is:

**AI = director + illustrator + asset preparation**

**Browser/Flutter runtime = actor + physics + timeline + interaction**

The finished SuperBook experience should feel like a story illustration that has come alive, not a sequence of AI photographs.

That distinction is the main lesson from every POC completed so far.
